# Встроенный транспорт CapybaraGram

Это исходники сетевого ядра для будущего режима подключения через WebSocket-инфраструктуру Telegram. Модуль ещё не подключён к интерфейсам Android и Windows. Он не гарантирует доступность Telegram у любого провайдера.

Основа — [by-sonic/tglock](https://github.com/by-sonic/tglock/tree/8617d25f3ae9bddb158a6703d1d02e453ebd39ba), версия `2.0.0-beta.14`, лицензия MIT. Папка `upstream` содержит 13 неизменённых файлов закреплённой версии. `source-pins.json` хранит SHA-256 и Git blob каждого файла. `prepare_core.py` проверяет весь набор и создаёт отдельную копию с изменениями; повторная подготовка в существующий каталог запрещена.

## Политика встроенного режима

- Только `127.0.0.1`, свободный порт назначает операционная система.
- Только MTProto; SOCKS5 и перенаправление произвольных адресов выключены.
- Случайный локальный секрет живёт в памяти и создаётся отдельно для каждого экземпляра. Это токен локального маршрута, не ключ аккаунта Telegram.
- Не более 128 одновременных клиентов, без неограниченной очереди задач.
- Незавершённые приветствия закрываются по тайм-ауту. Остановка отменяет активные подключения и освобождает разрешения.
- Диагностика экранирует управляющие символы; некорректные SOCKS-домены отклоняются без вывода их содержимого.
- Внешние Cloudflare Workers не настраиваются. Проверка TLS-сертификата и имени сервера сохраняется.

Встроенный режим использует `EmbeddedTunnel`, а не CLI: он не читает настройки, не сохраняет секрет на диск, не открывает ссылок и не запускает интерфейс tglock. CLI сохранён для совместимости тестов исходного проекта. Его прежнее поведение хранения секретов не является политикой CapybaraGram.

`native_api.h` и `native_api.rs` задают C ABI версии 1 для дальнейшей интеграции C++/JNI: создание, состояние и остановка через непрозрачный числовой дескриптор. Дескрипторы не переиспользуются; отозванный дескриптор недействителен. Разрешены до 16 отдельных экземпляров; общий Tokio-runtime использует два рабочих потока. Запуск и остановку следует вызывать из рабочего потока приложения. API сам не меняет прокси Telegram, настройки или сессию. Интерфейс ABI и его реальное применение в клиенте — отдельные этапы.

## Проверка

Workflow `Connection core runtime` запускается вручную. Он компилирует исходники закреплённым Rust 1.88.0 на Windows и Linux, выполняет исходные тесты и регрессии CapybaraGram, Clippy с ошибкой при предупреждении и сборку статической библиотеки. Сетевые тесты используют локальные синтетические WebSocket-узлы; реальные аккаунты и ключи Telegram не нужны.

До результата workflow компиляция и выполнение новых регрессий считаются неподтверждёнными. Даже успешный результат не подтверждает работу Telegram, переключение VPN, переход между Wi-Fi и мобильной сетью, ARM64 Android или интеграцию в приложение.

Для запуска вне GitHub нужен Rust 1.88.0 с Clippy, Python 3.12 и отдельный временный каталог:

```text
RUNNER_TEMP=<временный каталог>
python ci/connection/run_core_checks.py
```

Полная проверка транзитивных зависимостей остаётся отдельным этапом. Из проверенных конкретных предупреждений RustSec закреплённый `tungstenite 0.24.0` находится вне диапазона [RUSTSEC-2023-0065](https://rustsec.org/advisories/RUSTSEC-2023-0065.html), а `openssl 0.10.81` — вне диапазона [RUSTSEC-2025-0022](https://rustsec.org/advisories/RUSTSEC-2025-0022.html). Это не означает отсутствие всех уязвимостей в зависимостях.

Исходники GUI, браузерного интерфейса, внешнего Worker и установщик tglock сюда не включены. Лицензия оригинального ядра сохранена в `upstream/LICENSE`.
