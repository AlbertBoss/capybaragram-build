# Нативный контроллер подключения

`connection_worker` запускает и останавливает встроенный MTProto-транспорт вне UI-потока. Для подготовки используется точная версия ядра, прошедшая [Windows/Linux runtime 37184002484](https://github.com/AlbertBoss/capybaragram-build/actions/runs/37184002484). В `core-provenance.json` закреплены 24 хэша пакета и 17 хэшей подготовленных исходников.

Контроллер принимает одну ожидающую команду. Новое состояние заменяет прежнее; ответы также объединяются в один ожидающий вызов UI. Счётчик ревизии отбрасывает устаревший результат, а уничтожение контроллера отменяет ожидающие ответы, останавливает слушатель и присоединяет рабочий поток. `Ready` означает готовность локального слушателя, не подтверждение связи с Telegram.

Ручной workflow `Windows connection worker runtime` собирает точный Rust-транспорт и настоящий C++-контроллер на Windows и Linux с предупреждениями как ошибками. Проверяются включение, выключение с ожидающим старым ответом, 2000 быстрых запросов и уничтожение до доставки ответа. До успешного запуска эти сценарии считаются неподтверждёнными.

**Интеграция в Telegram пока отсутствует.** Эти файлы ещё не меняют маршруты, профиль или меню клиента. Дальнейшая интеграция должна применять временный маршрут только к MTProto-соединениям, хранить токен в памяти и оставлять обычные настройки прокси в прежнем сериализованном виде. Полная компиляция клиента, реальные вход и медиа, VPN и смена сети остаются отдельной приёмкой.
