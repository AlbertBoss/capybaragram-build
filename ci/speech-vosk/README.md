# Проверка лёгкой русской офлайн-альтернативы

Это отдельный тест Vosk 0.3.45 с публичной русской моделью small-ru-0.22,
а не подключённая функция Telegram-клиента. Предыдущая проверка Tiny/Base
показала ошибки смысла; новая альтернатива оценивается до изменения продукта.
Пять записей и эталоны остаются теми же заранее выбранными строками 0–4
MInDS-14. Полная атрибуция и CC BY 4.0 — в [пакете записей](../speech-ru/README.md).

Проверено происхождение: точный хеш Linux-wheel из метаданных PyPI, ELF x86_64,
безопасная структура архивов, все хеши файлов модели и шесть текстовых файлов
из `alphacep/vosk-api` на коммите `cf2560c9f8a49d3d366b433fdabd78c518231bec`.
Исходный API и лицензия просмотрены. Модель загружена с сайта автора и закреплена
SHA-256 полученного архива: сайт не публикует подписанную контрольную сумму.
Это не подтверждение сборки wheel из данного коммита и не полный аудит
нативных зависимостей Kaldi/OpenFst/BLAS. Старый wheel используется только для
оценки; его допуск в продукт требует отдельной проверки и исходной сборки.

Автоматический загрузчик из Python-обёртки автора не применяется: в выбранной
версии он получает изменяемый список моделей и распаковывает ZIP без закреплённого
хеша. `pip install`, requests, cffi, websocket, микрофон и сервер Vosk не нужны.
Используется только сверенная `libvosk.so` через C API с явным локальным путём.

Тест запускается вручную в одноразовом Ubuntu CI без владельческих ключей,
профилей и голосовых. Перед загрузкой библиотеки дочерний процесс проверяет
действующий запрет IP/Unix-сокетов и execve через libseccomp. Нет фонового сервера.
Действуют пределы 120 секунд CPU, 180 секунд ожидания, 1,5 ГиБ адресного
пространства и ограничение файлов; готовые наблюдения сохраняются по одному.
Это ограниченный тестовый процесс, а не доказательство полной изоляции файлов.

Первый запуск `37231752999` остановился до загрузки нативной библиотеки:
на сервере не оказалось FFmpeg. Распознавание и качество этим запуском не проверены.
Исправленный ручной workflow устанавливает FFmpeg и libseccomp2 из репозитория
Ubuntu на одноразовом сервере. Версии системных пакетов не закреплены;
их фактические версии и SHA-256 исполняемого FFmpeg сохраняются в отчёте.

Затем FFmpeg декодирует те же проверенные Opus-записи в PCM16
моно 16 кГц. Хеши PCM записываются в отчёт. Это другой декодер и
нативный Linux, поэтому время нельзя напрямую сравнивать с Android ARM64 под
трансляцией. Для каждой записи создаются отдельные модель и распознаватель;
эталонный текст не передаётся в словарь или подсказку распознавателя.

Отчёт содержит все пять ответов, число ошибок и пределы проверки. Технический
успех не означает принятое качество русского языка, Windows/Android UI или
работу с настоящим Telegram-аккаунтом. Модель клиента и обе сборки не меняются.
