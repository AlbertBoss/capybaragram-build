# Проверка лёгкой русской офлайн-альтернативы

Это отдельный тест Vosk 0.3.45 с публичной русской моделью small-ru-0.22,
а не подключённая функция Telegram-клиента. Предыдущая проверка Tiny/Base
показала ошибки смысла; новая альтернатива оценивается до изменения продукта.
Пять записей и эталоны остаются теми же заранее выбранными строками 0–4
MInDS-14. Полная атрибуция и CC BY 4.0 — в [пакете записей](../speech-ru/README.md).

Проверено происхождение: точный хеш Linux-wheel из метаданных PyPI, ELF x86_64,
безопасная структура архивов, все хеши файлов модели и шесть текстовых файлов
из `alphacep/vosk-api` на коммите `cf2560c9f8a49d3d366b433fdabd78c518231bec`.
Исходный API и лицензия просмотрены. Модель загружена с сайта автора и закреплена
SHA-256 полученного архива: сайт не публикует подписанную контрольную сумму.
Это не подтверждение сборки wheel из данного коммита и не полный аудит
нативных зависимостей Kaldi/OpenFst/BLAS. Старый wheel используется только для
оценки; его допуск в продукт требует отдельной проверки и исходной сборки.

Автоматический загрузчик из Python-обёртки автора не применяется: в выбранной
версии он получает изменяемый список моделей и распаковывает ZIP без закреплённого
хеша. `pip install`, requests, cffi, websocket, микрофон и сервер Vosk не нужны.
Используется только сверенная `libvosk.so` через C API с явным локальным путём.

Тест запускается вручную в одноразовом Ubuntu CI без владельческих ключей,
профилей и голосовых. Перед загрузкой библиотеки дочерний процесс проверяет
действующий запрет IP/Unix-сокетов и execve через libseccomp. Нет фонового сервера.
Действуют пределы 120 секунд CPU, 180 секунд ожидания, 3 ГиБ адресного
пространства и ограничение файлов; готовые наблюдения сохраняются по одному.
Это ограниченный тестовый процесс, а не доказательство полной изоляции файлов.

Первый запуск `37231752999` остановился до загрузки нативной библиотеки:
на сервере не оказалось FFmpeg. Распознавание и качество этим запуском не проверены.
Исправленный ручной workflow устанавливает FFmpeg и libseccomp2 из репозитория
Ubuntu на одноразовом сервере. Версии системных пакетов не закреплены;
их фактические версии и SHA-256 исполняемого FFmpeg сохраняются в отчёте.

Повторный запуск `37232565107` дошёл до загрузки первой модели и остановился
примерно через 120 секунд, не завершив ни одной расшифровки. Сигнал завершения
тогда не сохранялся; считать это доказанной ошибкой движка или CPU-лимита нельзя.
Следующий контролируемый опыт сохраняет код/сигнал завершения, стадии загрузки
и ограниченные замеры CPU/виртуальной/физической памяти. Проверяется гипотеза
о влиянии адресного ограничения: его повышают с 1,5 до 3 ГиБ при том же сетевом
запрете и пределах времени. Это ограничение виртуального пространства теста,
а не измеренное потребление памяти приложения. Входные модель, библиотека и
пять записей остаются прежними; успешное прохождение гипотезу само по себе не докажет.

Затем FFmpeg декодирует те же проверенные Opus-записи в PCM16
моно 16 кГц. Хеши PCM записываются в отчёт. Это другой декодер и
нативный Linux, поэтому время нельзя напрямую сравнивать с Android ARM64 под
трансляцией. Используется одна статическая модель и новый распознаватель для
каждой записи согласно контракту C API; модель освобождается в конце серии.
эталонный текст не передаётся в словарь или подсказку распознавателя.

Диагностика `37233637714` завершила первую расшифровку, затем остановилась
по родительскому пределу 180 секунд при второй загрузке модели. Пиковые замеры:
2 875 596 КиБ виртуального пространства, 268 372 КиБ физической памяти,
1,56 секунды CPU; журнал остановился на вычислении i-vector при повторной загрузке.
Сигнал SIGKILL отправил тестовый родитель. Причина внутренней остановки не доказана.
Следующая серия сохраняет те же входы и пределы, но проверяет предусмотренное
API совместное использование неизменяемой модели с пятью свежими распознавателями.
Даже её успех не примет повторное освобождение/загрузку модели, качество для любых
голосовых или готовность библиотеки к включению в продукт.

Отчёт содержит все пять ответов, число ошибок и пределы проверки. Технический
успех не означает принятое качество русского языка, Windows/Android UI или
работу с настоящим Telegram-аккаунтом. Модель клиента и обе сборки не меняются.

Источники: [официальная страница моделей](https://alphacephei.com/vosk/models),
[PyPI 0.3.45](https://pypi.org/project/vosk/0.3.45/),
[закреплённые исходники](https://github.com/alphacep/vosk-api/tree/cf2560c9f8a49d3d366b433fdabd78c518231bec).
Код теста — MIT; оригинальная Apache 2.0 находится в `UPSTREAM-LICENSE.txt`.

## Полученный результат общей статической модели

[37234600074](https://github.com/AlbertBoss/capybaragram-build/actions/runs/37234600074)
завершил все пять заранее выбранных записей с отдельными распознавателями.
Все ответы и ошибки сохранены в [RESULTS.json](RESULTS.json), хеш артефакта
и каждое число ошибок перепроверены независимо.

Получено 12 расхождений из 63 эталонных слов (19,05% WER). Ошибки по записям:
4/24, 3/15, 2/6, 3/10, 0/8. Четвёртый ответ искажает начальную фразу; качество
любых голосовых этим не принято. У исходного первого эталона тоже есть странная
формулировка; её не исправляли вручную ради уменьшения WER.

В этом Linux-процессе серия заняла 5,814 секунды, сумма распознавания — 4,643 секунды.
Пик RSS рабочего процесса — 266 292 КиБ, наблюдаемый пик виртуальной памяти —
2 662 604 КиБ. Это разные виды памяти. Скорость и память телефона не измерены,
а время нельзя напрямую сравнивать с переводимой ARM64-серией Whisper.

На тех же закодированных записях Whisper Tiny/Base дали 21/17 ошибок из 63;
у Vosk их меньше на этой небольшой выборке. Менять модель готового клиента
на основании этого результата пока нельзя: повторная загрузка зависает,
происхождение исходной сборки wheel и допуск платформенных библиотек остаются
отдельной работой. Повтор неизменённой успешной серии не требуется.
