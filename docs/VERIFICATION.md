## Русские голосовые: новая отдельная проверка

Подготовлен ручной `Android exact ARM64 Russian speech observations`. Он берёт
неизменённую ARM64 JNI-библиотеку из подписанной APK 37208052043, исходный Java-мост
и Android-декодер. Отдельный тестовый процесс без Internet распознаёт первые пять
русских строк [PolyAI MInDS-14](https://huggingface.co/datasets/PolyAI/minds14/tree/8123482db0c6a7b82694c1b92760a7e40e05c428)
в режиме автоопределения языка, как в клиенте. Первый образец дополнительно сравнивается
через AAC и с явным `ru`. Происхождение, CC BY 4.0, преобразования и эталоны сохранены.

Компиляция Java 8 против Android API 36 с `-Xlint:all -Werror`, хеши исходных строк,
шести подготовленных файлов и выбор настоящего JNI из APK проверены локально.
Первый запуск [37222395922](https://github.com/AlbertBoss/capybaragram-build/actions/runs/37222395922)
остановился по пределу 1200 секунд без итоговых расшифровок. Его артефакт получен
и проверен; этот запуск не подтверждает русское распознавание или его качество.
В помощнике добавлены немедленный вывод каждой записи, сохранение частичных
наблюдений и диагностика при остановке. Шесть синтетических проверок обработчика
тайм-аута прошли; обновлённый Java-код компилируется. Предел серии — 1800 секунд,
задания — 40 минут. Продакшен-библиотека, модель и выбранные записи не менялись.
Повторная серия [37224628064](https://github.com/AlbertBoss/capybaragram-build/actions/runs/37224628064)
завершилась: семь настоящих вызовов production ARM64 JNI, Opus и AAC дали текст.
Артефакт получен, хеши и последовательность записей сверены. На пяти заранее выбранных
Opus-записях с `auto` получилось 21 словесное расхождение из 63 эталонных слов,
WER 33,3%; один ответ содержит явно искажённую фразу. Для первого образца `ru`
дал тот же текст и WER, но сократил время с 224 до 102 секунд. Это один образец,
не основание обещать улучшение качества при смене языка. Вся серия выполнялась
через ARM64-трансляцию на эмуляторе; её скорость не переносится на телефоны.
Русское качество пока не принято. `TECHNICAL_PASS` подтверждает выполнение,
а качество показывается отдельно через эталоны, ответы и WER — число словесных
ошибок относительно эталона. Эта небольшая выборка и трансляция ARM64 не доказывают
скорость физических телефонов, качество любых голосовых или приёмку меню Telegram.
[Материалы и точный метод](../ci/speech-ru/README.md).

## Настоящий публичный обмен через встроенный транспорт

Подготовлен отдельный ручной `Public Telegram round trips through frozen embedded transports`.
Он отправляет только неавторизованный `req_pq_multi` через настоящий loopback-туннель
и проверяет ответ `resPQ` с тем же свежим nonce. Заданы восемь случаев: DC1–5,
203 и медиа-маршруты DC2/DC4. TLS-проверка остаётся включённой; внешние прокси
и Worker не настраиваются. Ключ аккаунта, API-данные и профиль не используются.

Подготовка 17 исходников Windows и 20 исходников Android TLS совпала с прежними
закреплёнными хешами и lockfile. В [37225872482](https://github.com/AlbertBoss/capybaragram-build/actions/runs/37225872482)
Rust-пробник собрался на обоих хостах; по два синтетических теста прошли.
Однако только 1 из 8 реальных ответов в каждом варианте прошёл строгий разбор,
остальные отклонены по длине тела/padding. Сетевая функция не принята.
В диагностическом повторе выводятся лишь структурные размеры; проверка ответа
не ослаблена, исходники production-ядра не меняются. В Windows используется MSVC14.44/SDK26100,
а Android TLS собирается для Linux-хоста: это не запуск ARM64 JNI или клиента.
Даже успешная проверка ограничена этой CI-сетью и не докажет вход, работу
российского провайдера или переходы VPN. [Метод и границы](../ci/connection-live/README.md).

## Текущая Windows-сборка и CMake

Сборка [37171862699](https://github.com/AlbertBoss/capybaragram-build/actions/runs/37171862699) завершилась на конфигурации Whisper: новый CMake 4.4 отклонил старую минимальную версию и неопределённую CMP0194 для MSVC. EXE с нечиталкой/голосом из этого запуска не получен. Совместимость добавлена только внутри функции подключения закреплённой сторонней зависимости; родительские политики и Android не переключаются. Строгая MSVC/Ninja-компиляция и настоящее распознавание тестового аудио прошли в [37180641106](https://github.com/AlbertBoss/capybaragram-build/actions/runs/37180641106): CMake 4.4.3, MSVC 14.44, предупреждения разработчика и устаревших политик считаются ошибками. Проверены 20 хэшей исходников и точный артефакт. Полная сборка с архивом, read-mode и голосом [37180751216](https://github.com/AlbertBoss/capybaragram-build/actions/runs/37180751216) прошла конфигурацию и нативные проверки настроек, затем остановилась при компиляции `voice_worker.cpp`: заголовок `QNetworkAccessManager` не найден. Закреплённый `external_qt` даёт общий Qt include, но не отдельный include QtNetwork; три заголовка изменены на `QtNetwork/...`. Составление патча и хэши обновлены. EXE из этого запуска не получен; повторная полная компиляция остаётся отдельным этапом.

При очистке архива нативный UI закрывает все просмотры только выбранного аккаунта до отзыва хранилища; проигрыватель останавливается до исчезновения окна. Буфер ответа очищается также при закрытом окне и ошибке выделения памяти. Это пока изменения исходников, ожидающие полной компиляции и проверки интерфейса.

## Сетевое ядро

В `ci/connection` включена закреплённая MIT-основа tglock `8617d25f3ae9bddb158a6703d1d02e453ebd39ba` и отдельный подготовщик встроенного режима. В проверенном снимке найдены удержание незавершённых SOCKS/MTProto-подключений без ограничения задач и вывод управляющих символов из имени назначения в журнал. В собственной копии добавлены тайм-аут, ограничение 128 клиентов, освобождение разрешений при отмене и очистка диагностики. Встроенный API использует только loopback, случайный токен в памяти и MTProto без SOCKS/произвольного forwarding.

Локально проверены происхождение 13 файлов, неизменность lockfile и точная подготовка 17 файлов. Компиляция Rust 1.88.0, Clippy с предупреждениями как ошибками и статические библиотеки прошли на Windows/Linux в [37184002484](https://github.com/AlbertBoss/capybaragram-build/actions/runs/37184002484). На каждой системе выполнены 113 тестов и 632 утверждения настоящего C++-вызова ABI, включая лимит экземпляров, остановку и отозванные дескрипторы. Два исходных теста внешнего Telegram явно пропущены. Локально сверены хэши артефактов, 24 исходников пакета и 17 подготовленных файлов; повторять этот набор без связанных изменений не требуется. Добавлен C ABI версии 1 для C++/JNI: до 16 экземпляров, два общих рабочих потока, непрозрачные непереиспользуемые дескрипторы. Ядро ещё не подключено к приложениям, работа Telegram с VPN и без него не подтверждена. Проверка исходников не охватывала GUI, внешний Worker и весь граф транзитивных зависимостей.

C++-контроллер в `ci/windows-connection` прошёл настоящую компиляцию и выполнение на Windows/Linux в [37185110803](https://github.com/AlbertBoss/capybaragram-build/actions/runs/37185110803): 13 проверок на каждой платформе, включая 2 000 быстрых запросов, одну ожидающую команду и один вызов UI, отзыв старого ответа и уничтожение до доставки. Семь хэшей исходников и артефакты сверены.

В `ci/windows-connection-native` подготовлена нативная интеграция: пункт меню, переключение текущего запуска для всех аккаунтов, временная подмена только параметров MTP-сессии, восстановление обычного прокси и приостановка его ротации. Сохранённые настройки и авторизация не переписываются. Шесть хостов и семь устанавливаемых файлов составлены поверх архива; проверки изменения входа, CRLF, повторного применения и коллизий прошли локально. Нативный UI ещё не скомпилирован и не принят.

Основной клиент использует статический release CRT: это подтверждено закреплённым [cmake_helpers](https://github.com/desktop-app/cmake_helpers/blob/428f37a41f936922cd3bb0159a357cca22ad359c/variables.cmake). Ручной workflow `Windows connection release compatibility` проверяет Rust с `+crt-static`, MSVC 14.44, SDK 10.0.26100.0, настоящие C++ ABI/контроллер, предупреждения линковщика и импорты CRT DLL. Проверка прошла в [37187970195](https://github.com/AlbertBoss/capybaragram-build/actions/runs/37187970195): MSVC 14.44.35207, SDK 10.0.26100.0, Rust 1.88.0, 632 настоящих ABI-проверки и 13 проверок контроллера с 2 000 быстрых запросов. Динамических CRT DLL и предупреждений линковщика нет. Сверены артефакт, девять файлов интеграционного пакета и 17 подготовленных исходников. Два предыдущих коротких запуска остановились в отчёте: регистр Windows-переменной окружения и распознавание эквивалентного флага `-MT`; оба исправлены по фактическим логам. Полный клиент и реальные переходы VPN остаются отдельными этапами. Режим пока доступен после входа; звонки и другие приложения сохраняют обычный маршрут.

Android-вариант в `ci/android-connection` использует отдельный замороженный lockfile и Rustls 0.23.45, WebPKI 0.103.15, ring 0.17.14 и публичные корни 1.0.9. Windows-пакет не менялся. В [37192578101](https://github.com/AlbertBoss/capybaragram-build/actions/runs/37192578101) прошли 90 тестов, в том числе настоящий TLS/WebSocket с доверенным сертификатом, отказ по чужому имени сервера и недоверенному сертификату, Clippy с предупреждениями как ошибками и 632 настоящих C++ ABI-проверки. JNI собран для ARM64 и x86_64 на NDK 27.2.12479018 / API 23: ELF, три экспорта, 16 КиБ выравнивание и только системные импорты проверены. Локально сверены артефакт, 12 файлов пакета и замороженный lockfile; 20 подготовленных файлов не менялись при сборке. Первый запуск выявил отсутствие ответа `binary` у синтетического WebSocket-сервера: исправлен тестовый сервер; проверка сертификатов не отключалась.

По состоянию на 2026-10-04 проверены 111 закреплённых версий lockfile через базу [OSV](https://osv.dev/), совпадений с известными уязвимостями нет. Это проверка базы, не полный аудит кода. Интеграция в основной клиент, вход в Telegram и VPN-переходы ещё не приняты. Два внешних теста Telegram явно пропущены.


Настоящее выполнение JNI на изолированном Android 11 / API 30 x86_64 прошло в [37193035153](https://github.com/AlbertBoss/capybaragram-build/actions/runs/37193035153). Проверены некорректные массивы, ABI/readiness, независимые экземпляры, отказ SOCKS до внешнего подключения, идемпотентная остановка, отозванные дескрипторы и повторное создание без переиспользования ID. 427 утверждений включают повторную проверку байтов токена, а не 427 пользовательских сценариев. Артефакт, 15 хэшей пакета и идентичность исполняемой JNI-библиотеки сверены. Исходные 90 Rust-тестов и 632 C++ ABI-проверки также прошли; это необходимая проверка границы Android, не приёмка GUI или Telegram. Реальное ARM64-устройство, сеть провайдера и смена VPN не проверены.

### Добровольные события скриншотов Android

Выключенный по умолчанию модуль использует OS callback Android 14+ только в обычном
личном чате. Подготовка исходников, 21 условие допуска и отзыв владельца/настройки
в очереди запроса проверены на уровне исходников и Java-политики; исполнение
на Android и серверный результат остаются открытыми. Точная область неизвестна,
чужой несообщающий клиент не обнаруживается. [Описание](SCREENSHOT-EVENTS.md).
